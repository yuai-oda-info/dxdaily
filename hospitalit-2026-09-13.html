きょうの障害・脆弱性メモ（院内SEの視点）

AOMEI Backupper のカーネルドライバ amwrtdrv.sys に権限昇格の脆弱性（CVE-2026-12780）

AOMEI Backupper 8.4.0 のカーネルドライバ amwrtdrv.sys に権限昇格の脆弱性（CVE-2026-12780、CWE-732：重要なリソースに対する不適切なパーミッションの割り当て）。ドライバのデバイスが誰でもアクセス可能な状態で公開されており、非特権のローカル利用者が物理ディスクへ直接書き込める。OS起動前のコード実行によりHVCIやWindows Defenderの回避に至る可能性がある。JVNVU#95258183／CERT/CC VU#687587。ベンダ（AOMEI Technology）からの見解は文書更新時点で未提示で、修正版は明示されていない。緩和策は、修正版への更新、アンインストール、脆弱なドライバサービスの無効化、多層防御としてのSecure Boot有効化。

今日確認すること：①資産台帳と配布管理ツールでAOMEI Backupperの導入端末・サーバを全件抽出する（無償版が部門単位で入っている場合が多い）→②該当機で sc query amwrtdrv によりドライバサービスの有無と状態を確認し、業務影響を確認のうえサービス停止・無効化またはアンインストールを実施する→③代替のバックアップ経路（別製品・スナップショット・テープ）で当日分のバックアップ成否を確認する→④対応した端末・サーバの機器名／OS／実施内容／実施者／日時を台帳とインシデント記録に残す。あわせてUEFI Shell経由のSecure Boot回避（VU#718077）の対象となるCisco UCS等のファームウェア版数を棚卸しに加える。きょうはバックアップ製品そのものを「守る対象」として台帳に載せ直しましょう。

公表日：2026-09-11新着公的JVN／CERT/CC

用語解説院内SEの実務でよく出る用語（毎日更新）

JFAGYコード
アレルギー等情報を電子カルテ情報共有サービスで交換するための標準コードで、特定原材料29品目を含む食物アレルギー原因物質の識別に用いる。
OBX-14
HL7のOBXセグメント第14フィールドで検査日時を表し、SS-MIX2標準化ストレージ仕様書Ver.1.2jでADTメッセージ内での使用が有効化された。
amwrtdrv.sys
AOMEI Backupperが導入するカーネルモードドライバで、8.4.0ではデバイスが誰でもアクセス可能なため物理ディスクへの直接書き込みを許す（CVE-2026-12780）。
HVCI
Hypervisor-protected Code Integrityの略で、Windowsがハイパーバイザを使ってカーネルコードの完全性を検証する機能。OS起動前のコード実行で回避されうる。
UEFI Shell
UEFIファームウェアに組み込まれたコマンド環境。dmem・mmで物理メモリを読み書きでき、起動エントリ経由で呼び出せるとSecure Bootの回避に使われる（VU#718077）。
基幹インフラ制度
経済安全保障推進法に基づく特定社会基盤役務の審査制度で、医療情報化推進方針（案）では対象病院のサイバーセキュリティ対策状況を点検する枠組みとして位置づけられる。

GLOBAL HOSPITAL IT｜海外の病院IT

USASPIフラッシュに組み込まれたUEFI ShellモジュールによりSecure Bootを回避できる（VU#718077）

起動オプション削除処理のロジック欠陥により、UEFI起動エントリを追加できる攻撃者が、標準的な実行防止策を施していてもSPIフラッシュ内のUEFI Shellを参照できる。Shellのdmem・mmコマンドでSecure Boot関連のメモリ値を上書きでき、再起動やOS再インストールをまたいで存続するブートコンポーネントやカーネルレベルのソフトウェアを読み込める。影響が確認されたのはAMI（CVE-2026-33197）、Cisco（CVE-2026-20293、UCSサーバ／アプライアンス）、GIGABYTE（CVE-2026-33197）、Insyde Software（CVE-2026-6485）。IntelとPhoenix Technologiesは影響なし。Dell、HP、Lenovo、Microsoft、Supermicro、ASUSTeKほか16社以上は状況不明。対策はOEMのファームウェアパッチ適用と、UEFI起動エントリ変更の監査。

日本の院内SEへ：国内の病院情報システムでも仮想化基盤やサーバにCisco UCSやAMI／Insyde系ファームウェア搭載機が使われており、電子カルテ・PACSのホストが対象になりうる。AOMEI Backupperの緩和策として挙げられたSecure Boot有効化が、この脆弱性では前提として崩れる点が実務上の要点。

日本でも使える点：サーバ・仮想化ホストの資産台帳に「ファームウェア提供元（AMI／Insyde／OEM独自）」と「現行ファーム版数」の2列を追加し、Cisco UCS等の該当機を抽出してOEMのパッチ提供状況を保守業者に照会する。UEFI起動エントリの変更検知を監査対象に加える。
制度が異なる点：日本ではサーバのファームウェア更新が保守業者の作業範囲に含まれ、医療機関側に版数情報が渡っていないことが多い。CERT/CCは利用者側でのOEMパッチ適用と監査を前提に書いているが、国内では保守契約の作業範囲と停止調整の合意形成が先に必要になる。
